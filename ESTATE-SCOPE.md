# ESTATE SCOPE

The canonical mining scope is the user's ENTIRE recoverable mathematical estate across sessions, days, projects, and storage surfaces. Day labels are provenance only.

## Included source families

- Day-1 raw GPT mine and every novelty/audit/mining derivative.
- Day-2 raw/audit/mining releases and all Pass 1+ cumulative estates.
- All Erdős problem attack sessions, including single-problem experiments and later multi-problem campaigns.
- MSL / alien-math language development, canonical MSL releases, decoding sessions, proof-out experiments, and vocabulary/grammar evolution.
- Lean/formalizer outputs, source files, kernel receipts, theorem declarations, proof bodies, failed formalizations, repair attempts, axioms/holes indexes, and certificates.
- Mathematical theorem/gold ledgers, claim registries, problem dossiers, route histories, branch composites, obligations, contradiction histories, killed routes, revival requirements, cross-problem fusions, and transfer candidates.
- Computational witnesses, exact numeric payloads, scripts, solver/search recipes, finite censuses, certificates, and reproducibility artifacts.
- Existing public/private repositories containing project mathematics, when recoverable and relevant.
- Earlier math conversations/releases that predate the current Day-1/Day-2 naming.
- Future mathematical runs: every run self-mines into ORE before completion.

## Excluded by default

Non-mathematical personal/business/project material unless it contains mathematical claims, proofs, formalization, computation, or reusable mathematical infrastructure directly relevant to the estate.

## Discovery surfaces

1. Current runtime/conversation uploads.
2. ChatGPT Library files from prior sessions.
3. Google Drive files when explicitly part of the math campaign or transport/storage.
4. GitHub repositories belonging to the math estate.
5. Heavy cumulative release assets / archived source bytes.

## Estate census rule

Every discovered source artifact receives a stable source record with at least:

- source identifier / storage location
- filename/path
- content hash when bytes are available
- provenance day/session/project labels when known
- whether exact bytes are recoverable
- which extraction grammars have consumed it
- latest cumulative release containing its ore/provenance

A source being represented in a derived report does NOT count as raw-source saturation. Direct bytes, derived registries, and graph structure are independent mining surfaces.

## Cross-session rule

`MEMORY.md` is the compact router. `RESUME.md` is the current checkpoint. `LOG.md` is chronological history. The ORE estate is the actual mathematical memory.
